Privacy

What stays on your computer, and every connection the app, the browser extension, a team server and this website make. Each statement was checked against the source code.

Not yet reviewed by a lawyer. This page is the maintainers' plain description of what the software does. It is not legal advice. The fuller text, with the source file behind each statement, is docs/PRIVACY.md in the repository.

In short

  • Your vault lives on your computer, encrypted. The project has no server that receives it and no way to see your credentials.
  • There is no telemetry, analytics, crash reporting or advertising in the app, the extension or the server. There is no account with us to create.
  • The app connects to the internet for a short, fixed list of reasons, all listed below.
  • If you join a team, its server stores only ciphertext it cannot read, plus the e-mail addresses and membership it needs to route it. Whoever runs that server is responsible for it.

What stays on your computer

  • The vault: your credentials, their notes and where each may be used. Encrypted on disk, in a folder only the SecretBroker service account can read.
  • Activity: what was used, filled, copied, approved or refused, when and by which program. Encrypted, and readable only while the vault is unlocked.
  • The search for copies of your keys: it reads files on your computer (AI conversations, terminal history, program settings, project folders and their git history). Nothing it reads or finds is sent anywhere.

What your AI provider sees

AI agents talk to SecretBroker on your own computer. They receive the results of what they ask for with the secrets removed, never the secrets. They do see the names of your credentials, the Instructions for the AI you wrote and the redacted results, and those become part of your conversation with the AI, under that provider's own privacy terms. Private notes, passwords and keys are never given to the AI.

The browser extension

  • It talks only to the SecretBroker app on the same computer, through the browser's native messaging. It sends nothing to the project or to anyone else, and loads no code from the internet.
  • To do its job it reads the address of the tab you are on and the login fields of the page, and, when you send a login form, the username and password you typed, so the app can offer to save them. They are stored only if you click to save.
  • The one thing it asks the internet for is a website's own icon, fetched from that site without cookies and without saying which page asked. It never uses an icon service.

The team server

A team server is optional. The project runs none: each one is installed and run by the organization that uses it, and that organization is responsible for the data on it.

It stores accounts (e-mail address, the name you chose, public keys, and your private keys encrypted so that only your password or recovery code opens them), devices (the name of each signed-in device and when it was last seen), organizations (their names, members, roles and pending invitations) and shared credentials as ciphertext only, with who may open each collection, sizes, counts and times, and a log of who did what.

It never receives credentials, their names or notes in clear, collection names, your account password, your recovery code, your master password, or anything you did not share.

If its operator set up e-mail, it sends two kinds of message and no others: the code that verifies your address, and invitations. A server installed with the one-command installer asks GitHub once a day for a newer signed version of itself.

This website

  • It is a set of static files hosted on GitHub Pages. GitHub, as the host, receives your IP address when you load a page, like any web host.
  • It sets no cookies and runs no analytics, and loads no fonts, scripts or images from other servers. The pages forbid it themselves with a content security policy.
  • One exception, on the home page: the download buttons ask GitHub's public API (api.github.com) which release is the latest, to link straight to the right installer.
  • Your browser keeps two small things for this site: the theme you chose and, during your visit, the answer about the latest release. Neither is sent anywhere.

Your choices

  • Key tests and leak checks: Settings › Security › Check that keys work, or each credential, down to “Never”.
  • The search for copies: Settings › Copies of your keys.
  • The browser extension: Disconnect in Settings › Browser, or remove it from the browser.
  • A team account: disconnect in Team › Your account. To have the account deleted, ask whoever runs the server.
  • Everything: uninstalling asks whether to delete the vault. If you keep it, it stays on your disk, encrypted, until you delete it.

Questions

Open an issue on GitHub. It is public, so never paste a secret there. To report a security problem in private, see the security policy.
