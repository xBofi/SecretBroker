# Translating SecretBroker

SecretBroker is written in Spanish (the source) and English (the fallback). Every other language is a set of
JSON files next to those two: adding a language means adding files, never touching code. The app finds the
languages by the files that exist and offers them in **Ajustes › Apariencia › Idioma** (and on the welcome screen),
each in its own name («Deutsch», «Русский», «中文»). Until the user picks one, it follows the language of the system,
and falls back to English.

## Files to create for a new language

Use the language code as Chromium/WebView2 reports it (`navigator.language`): `de`, `fr`, `pt`, `pt-BR`, `zh`,
`zh-TW`, `ru`, `bg`… A plain code (`pt`) also serves its variants (`pt-PT`) unless a more specific file exists.

| File | What it holds | Start from |
|---|---|---|
| `secretbroker/web/locales/<code>.json` | Everything the app's window shows (≈1,400 messages). | `en.json` |
| `secretbroker/locales/<code>.json` | Texts the app's Python side writes: errors the service returns, notifications, the menu of the icon next to the clock, credential templates, provider links. | `en.json` |
| `extension/_locales/<code_with_underscore>/messages.json` | The browser extension (`pt_BR`, `zh_TW`: Chrome's format uses `_`). | `en/messages.json` |

Copy the English file, keep every key and translate the values. Do not add or remove keys, and do not rename the file
of an existing language. The installer (`installer/SecretBroker.iss`) speaks Spanish and English only for now;
adding a language there means a `[Languages]` line and its `[CustomMessages]`, and it is optional. The same goes for
the macOS package: `packaging/macos/resources/<code>.lproj/` (the installer's welcome and conclusion pages) and
`packaging/macos/lproj/<code>.lproj/InfoPlist.strings` (the app's Info.plist texts); without them macOS shows English.
The macOS build gives the app a `<code>.lproj` folder for every window locale by itself, so the system's own sheets
(Touch ID, Keychain) appear in the user's language.

Not translated on purpose: the AI-facing texts (`secretbroker/mcp_server.py`, tool descriptions), the `sb`
command line, the logs, and the server (`server/`).

## The format

**Placeholders** are named, in braces: `"Rotar {name}"`. Keep each placeholder exactly as it is (same name, any
position); never translate what is inside the braces. Double braces are not placeholders: `{{value}}` and
`{{password}}` are literal text the user types into SecretBroker, keep them as they are. In the extension they are
`$name$` and each message has a `placeholders` block: copy that block unchanged.

**Plurals** are objects with the CLDR plural forms of your language:

```json
"common.credentials_count": { "one": "{count} Zugangsdaten", "other": "{count} Zugangsdaten" }
"common.credentials_count": { "one": "{count} учётная запись", "few": "{count} учётные записи", "many": "{count} учётных записей", "other": "{count} учётной записи" }
"common.credentials_count": { "other": "{count} 个凭据" }
```

Use the forms your language has (`zero`, `one`, `two`, `few`, `many`, `other`; see the
[CLDR plural rules](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html)). `other` is
always required. A form for an exact number is written `"=0"`, `"=1"`… and wins over the category. In languages whose
`one` also covers 21, 31… (Russian, Ukrainian, Croatian…), keep `{count}` in the `one` form instead of writing the
word for «one».

**Dates, times, numbers and lists** are formatted by the app in the user's language (Intl): never write a date or a
number in a message. Words like «hoy», «ayer», «mañana» come from the system too.

**Typographic quotes**: Spanish uses «…», English “…”. Use your language's own (German „…“, French « … »).

**Length**: the layout takes texts up to ~40% longer than English, and buttons wrap or end in an ellipsis. Still, keep
buttons and menu items short: a verb and, at most, an object.

## Tone

- Informal and direct: address the user as «tú» (German «du», French «tu», Russian «ты»… whatever is natural for
  consumer software in your language; if your language's software is formal by default, prefer the formal one).
- Short, plain and friendly. Say what happens and what to do, without jargon: «No se pudo sincronizar. Se
  reintentará solo.», not «Error de sincronización (código 503)».
- No exclamation marks, no blaming the user, no «please» in every sentence.
- Sentence case for buttons and titles («Crear colección», «Create collection»), not Title Case.
- Keep the meaning of security texts exact: what the AI can or cannot see, what the server cannot read, what cannot
  be undone. When in doubt, translate literally from English and ask.

## Checking a translation

```
python tools/check_locales.py          every language
python tools/check_locales.py de       one
```

It checks, for the three catalogs, that the language has exactly the keys of English, the same placeholders, valid
plural forms for that language (and warns about missing ones), and no empty texts; and that every key the page's code
uses exists. It exits with 1 if something is wrong.

Then look at it: run the app (`python -m secretbroker.app` from a checkout, or the installed one), choose the language
in Ajustes and go through Credenciales, Salud, Acceso de la IA, Equipo, Actividad, Ajustes, the lock screen and the
first-run screens. `tests/test_gui.py` does that in English and fails if a Spanish text is left; it saves screenshots
(`en-*.png`) in the folder it prints at the end.

## For developers

- Page: `t('section.key', { name })`, `tn('section.key', count, { … })` for plurals, `fmtDate`, `fmtRelative`,
  `fmtNumber`, `fmtList`, `compareText` (`secretbroker/web/i18n.js`). Tables of labels built at load time go through
  `localized(() => (…))` so they follow a change of language. New texts go to `es.json` and `en.json` together.
- Python: `from .i18n import tr` and `tr("module.key", **params)`; plural messages take `count`. The app sends its
  language with every request (`client.LANG`), so the service answers in it; requests without one (the AI, `sb`, the
  browser) get the last language the app used. Texts kept as data in Spanish (template labels, provider links) are
  translated where they are handed out, with `i18n.localize()`; their keys are made from the text
  (`i18n.source_key`), so changing a Spanish label there needs its entry in the catalogs updated.
- Extension: `msg('key', { name })` over `chrome.i18n`; the values are passed in the order of the message's
  `placeholders`.
